# InvoiceEye project instructions

- Work on the main branch only.
- Use the existing linked Supabase production project. Ask before changing the production database schema or performing destructive operations.
- Create a meaningful Git commit after each completed and tested development milestone. Use descriptive conventional commit messages and keep unrelated features in separate commits.
- Update documentation when functionality changes.
- Never commit credentials, private environment files, raw development transcripts or private backups. Inspect staged files and scan for credentials before committing.
- Preserve genuine history. Never fabricate commits, backdate timestamps or present a reconstructed checkpoint as an original implementation-time commit.
- Do not push incomplete or untested changes. The initial GitHub push and any deployment require separate approval from the project owner.
